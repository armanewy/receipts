# Scenario Output Contract

Future scenario generators must output semantic objects, not prose templates. The structure below is required.

## 1. Scenario Metadata

- Title.
- Category.
- Tone.
- Estimated playtime.
- Intended difficulty.
- Starting app.
- Apps used.
- Primary transformation types.
- One-sentence semantic promise.

## 2. Surface Event Semantics

- Artifact type.
- Emotional charge.
- Apparent target.
- Immediate question.
- Why a user keeps scrolling.

## 3. Public Interpretation Semantics

- Apparent actor.
- Apparent motive.
- Apparent timeline.
- Apparent wronged party.
- Viral supporting artifact.
- Emotional reason it spreads.
- What it gets right.
- What it gets wrong.

## 4. Actual Causal Chain

- Responsible individual.
- Motive/pressure.
- Action taken.
- Manipulation/concealment method.
- True timeline.
- Intended public belief.
- Unintended trace left behind.
- Why this explanation is more satisfying.

## 5. Transformation Types Used

List each type and explain how it functions in the scenario.

## 6. App Semantic Roles

For each app:

- Role in scenario.
- Key artifact.
- Misleading surface.
- Truth it reveals.
- Unlock trigger.
- Adversarial concern.

## 7. Progressive App Disclosure

- Starting app and why.
- Unlock 2 trigger.
- Unlock 3 trigger.
- Unlock 4 trigger.
- What question each unlock answers.
- What new question each unlock creates.

## 8. Receipt Graph

For each receipt:

- Receipt ID.
- Source app.
- Surface type.
- Raw artifact description.
- Apparent meaning.
- Actual meaning.
- Supports report slot: WHO, WHY, WHEN, HOW, or CONTEXT.
- Dependencies.
- Required, optional, or misleading.
- Production notes.

## 9. Contradiction Ladder

- Surface belief.
- First wobble.
- Cross-app context.
- Timeline break.
- Source/method link.
- Motive/benefit.
- Confirmation bundle.

## 10. Report Requirements

- Correct WHO.
- Correct WHY.
- Correct WHEN.
- Correct HOW.
- Minimum required receipts.
- Optional supporting receipts.
- Accepted substitute receipt bundles, if any.

## 11. Plausible Wrong Theories

For each:

- Why plausible.
- What it explains.
- What it fails to explain.
- Social-native feedback the product could give.

## 12. Ending Semantics

- Public story.
- True story.
- Emotional payoff.
- Why the false story spread.
- How the feed reacts after the report.

## 13. Doomscroll Beat Map

For each beat:

- User action.
- Dopamine/micro-reward.
- New uncertainty introduced.

## 14. Production Feasibility Notes

- Realistic photos needed.
- Short videos needed.
- Comments/text content needed.
- Risky assets.
- Assets that can be made from stills.
- Assets that require careful continuity.

## 15. Adversarial Critique

- What is too obvious.
- What is too hidden.
- What app feels unnecessary.
- What receipt feels too confession-like.
- Where players might get stuck.
- What feels unrealistic.
- What should change before playtesting.

## 16. Scorecard

Use `docs/SCENARIO_RUBRIC.md`. Include a score from 1 to 5 for every rubric category and a short rationale for each.
