# Receipts Agent Instructions

This repository is currently in planning mode for a mobile-first, game-like social browsing product called Receipts. Do not implement code, app architecture, or production systems unless the user explicitly asks for that work.

## Required Reading

Before making changes, future agents must read:

1. `AGENTS.md`
2. `docs/PROJECT_NORTH_STAR.md`

Read other docs under `docs/` when the task touches scenario design, content, terminology, or production planning.

## Product Frame

Receipts is a solo mobile-first lurker mystery experience. The player should feel like they are browsing familiar social apps and saving social artifacts that help them build a theory. The fantasy is not professional inquiry or procedural problem-solving. The player is a lurker.

Preserve the lurker framing in all artifacts:

- Use browsing, scrolling, tapping, saving, comparing, and posting-language as the core verbs.
- Use receipts, threads, theory, report, who, why, when, how, source, post, clip, story, DM, profile, comment, expose, and app unlock language.
- Avoid product-facing detective, law-enforcement, and crime-scene vocabulary, including "detective," "case file," "investigation," "crime scene," "police," "suspect," "culprit," "perp," and adjacent terms.

## Scenario Rules

Scenarios must be semantic structures, not sentence templates. Do not rely on canned story formulas. Every major scenario or design artifact must include an adversarial critique section.

Scenario work should encode:

- Surface event
- Public interpretation
- Actual causal chain
- Transformation types
- App-specific roles
- Receipt graph
- Contradiction ladder
- Report requirements
- Plausible wrong theories
- Ending semantics
- Adversarial critique

Scenarios should usually use multiple fictional social app analogs and should not become single-platform-only unless the user explicitly asks for that constraint.

Most scenario resolutions should center on an individual responsible party. Companies, brands, groups, and platforms may provide pressure, context, or incentives, but should not usually be the central answer.

## Content And IP Guardrails

Use realistic fictional people and fictional app surfaces. Do not use real people, public figures, lookalikes, real platform names, exact platform UI, or real platform branding.

Mysteries should support internet drama beyond disappearances or crimes, including relationship truth, friend-group betrayal, fake identity, creator feud, staged scandal, scam or fake guru, reputation manipulation, public apology, callout drama, platform-adjacent manipulation, and social status sabotage.

## Repo Practice

Prefer durable docs under `docs/` over ephemeral chat answers. Keep changes scoped to the requested wave or task. End each task with a concise status summary describing created or changed files and any assumptions.
